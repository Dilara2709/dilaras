
# Архитектура

## Схема из трёх узлов

```text
Vue 3 + Vite          ASP.NET Core          PostgreSQL
localhost:5173 -----> localhost:5000 -----> обычно :5432
               HTTP                запросы к БД
```

**Архитектура web-ИС семестра**

Тема проекта: разработка программного обеспечения
для организации социального взаимодействия попутчиков
в поездах дальнего следования.

Главная сущность — поездка (Trip).
Справочник — тип вагона (Carriage).
Поле-ссылка на справочник — carriageId.

## Пояснение

- **Vue 3 + Vite** (`localhost:5173`) — клиент.
  Отображает экран входа, список поездок и форму
  создания поездки. Позволяет пользователю указать
  маршрут, выбрать тип вагона и ввести описание.
  Отправляет HTTP-запросы к API и отображает
  полученные данные и сообщения об ошибках.

- **ASP.NET Core** (`localhost:5000`) — сервер.
  Обрабатывает HTTP-запросы, проверяет входные данные,
  применяет правила изменения статусов поездок,
  проверяет права пользователей и выполняет
  назначение проводника.
  Обеспечивает взаимодействие с базой данных.

- **PostgreSQL** (обычно `:5432`) — хранилище.
  Предназначено для хранения поездок, справочника
  типов вагонов и пользователей.
  Обеспечивает целостность связей между сущностями
  и сохранение данных после перезапуска сервера.

## Стрелки

```text
Vue -> ASP.NET Core
Пример: POST /api/trips

ASP.NET Core -> PostgreSQL
Запросы к базе данных
```

Клиент отправляет HTTP-запросы серверу.
Сервер проверяет данные и выполняет необходимые
операции с базой данных.

Результат возвращается клиенту в формате JSON.

## Почему браузер не лезет в PostgreSQL напрямую

Прямой стрелки от браузера к базе данных нет:
иначе клиент получает доступ к данным и может
обойти серверные правила.

Все операции с данными выполняются через API.

Это позволяет:

- проверять корректность входных данных;
- разграничивать права пользователей;
- контролировать допустимые переходы статусов;
- обеспечивать целостность данных;
- не передавать клиенту параметры подключения к БД.

## Роли в системе

| Роль | Создаёт | Назначает | Меняет статус |
|---|---|---|---|
| Пассажир | да | нет | отменяет свою поездку в статусе New |
| Проводник | нет | нет | да, только назначенную ему поездку |
| Администратор | нет | да | нет |

Проводник не может назначать себя
самостоятельно.

Назначение ответственного выполняется отдельно
от изменения статуса поездки.

Допустимые переходы статусов:

- New -> InProgress.
- InProgress -> Closed.
- New -> Cancelled.

Статусы Closed и Cancelled являются конечными.
