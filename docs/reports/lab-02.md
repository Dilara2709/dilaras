
# Отчёт по лабораторной работе 2

## Цель

Зафиксировать архитектуру системы организации
социального взаимодействия попутчиков в поездах
дальнего следования: определить сущности, ключи
и HTTP-запросы, а также объяснить, почему браузер
не обращается к PostgreSQL напрямую.

## Архитектура

```text
Vue 3 + Vite          ASP.NET Core          PostgreSQL
localhost:5173 -----> localhost:5000 -----> обычно :5432
               HTTP                запросы к БД
```

Vue 3 отвечает за пользовательский интерфейс:
экран входа, список поездок и форму создания поездки.

ASP.NET Core отвечает за обработку запросов,
валидацию данных, проверку прав пользователей
и изменение статусов поездок.

PostgreSQL предназначена для хранения поездок,
типов вагонов и пользователей.

Прямой стрелки от браузера к базе данных нет:
иначе клиент получает доступ к данным и может
обойти серверные правила.

## Модель данных

Сущности:

- `Carriage` — справочник типов вагонов.
- `Trip` — главный объект, поездка.
- `User` — пользователь.

Ключи:

- `id` — машинный первичный ключ (PK);
- `number` — человеческий номер поездки,
  не замена id;
- `carriageId` — внешний ключ (FK) на справочник
  типов вагонов;
- `createdByUserId` — внешний ключ на пользователя,
  создавшего поездку;
- `assigneeUserId` — внешний ключ на назначенного
  проводника; при создании может
  быть пустым.

Проверка 3НФ: название типа вагона хранится
в сущности Carriage один раз. Trip содержит
внешний ключ carriageId.

При переименовании типа вагона меняется одна
строка справочника, поэтому название не дублируется
в поездках.

Данные пользователей хранятся отдельно в User,
а поездки содержат ссылки на пользователей.

## API

Основной путь API — `/api/trips`.

Получение списка и создание поездки:

```text
GET /api/trips
POST /api/trips
```

Назначение проводника и смена
статуса — разные действия:

```text
PATCH /api/trips/{id}/assignee
PATCH /api/trips/{id}/status
```

Допустимые статусы:

- `New` — новая.
- `InProgress` — в процессе.
- `Closed` — завершена.
- `Cancelled` — отменена.

Отмена поездки — перевод в статус Cancelled,
а не удаление строки.

## Матрица требований

| Требование ЛР1 | Поле или сущность | Запрос | Критерий |
|---|---|---|---|
| ФТ-1. Создать поездку | Trip, title, carriageId, description | POST /api/trips | 1 |
| ФТ-2. Назначить проводника | assigneeUserId | PATCH /api/trips/{id}/assignee | 2 |
| ФТ-3. Перевести поездку в работу | status | PATCH /api/trips/{id}/status | 3 |

## Роли и права

| Роль | Создаёт | Назначает | Меняет статус |
|---|---|---|---|
| Пассажир | да | нет | отменяет свою поездку в статусе New |
| Проводник | нет | нет | да, только назначенную ему поездку |
| Администратор | нет | да | нет |

Проводник не может назначать себя
самостоятельно.
