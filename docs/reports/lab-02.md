# Отчёт по лабораторной работе 2

## Цель

Зафиксировать архитектуру системы планирования и анализа финансов юридического лица: какие сущности, ключи и HTTP-запросы используются, и почему браузер не обращается к PostgreSQL напрямую.

## Архитектура

```text
Vue 3 + Vite                    ASP.NET Core                     PostgreSQL
localhost:5173  -------------> localhost:5000  -------------->  обычно :5432
                     HTTP                         запросы к БД
```

Прямой стрелки от браузера к базе нет: иначе клиент получает доступ к данным и обходит серверные правила.

## Модель данных

Сущности: `BudgetItem` (справочник), `FinancialOperation` (главный объект), `User` (пользователь).

Ключи:

- `id` — машинный первичный ключ (PK);
- `number` — человеческий номер записи, не замена id;
- `budgetItemId` — внешний ключ (FK) на справочник;
- `assigneeUserId` — внешний ключ на пользователя; при создании может быть пустым.

Проверка 3НФ: название статьи бюджета хранится в сущности BudgetItem один раз. FinancialOperation содержит внешний ключ budgetItemId. При переименовании статьи меняется одна строка, поэтому текст названия не дублируется в операциях.

## API

Назначение исполнителя и смена статуса — разные действия:

```text
PATCH /api/operations/{id}/assignee
PATCH /api/operations/{id}/status
```

Статусы только: `New`, `InProgress`, `Closed`, `Cancelled`. Отмена - `Cancelled`, а не удаление строки.

## Матрица требований

| Требование ЛР1 | Поле или сущность | Запрос | Критерий |
|---|---|---|---|
| Создать операцию | FinancialOperation, title, budgetItemId, description, amount | POST /api/operations | 1 |
